# Journal2

React 19 + Vite + Recharts frontend, Express / Vercel shared API, MongoDB persistence. Development branch: `codex/journal-audit`. No production deployment has been performed.

## Local development

Use Node 22 LTS and npm. `npm run dev` uses MONGODB_URI when configured. Otherwise it starts a loopback-only MongoDB development process with durable WiredTiger storage in ignored `.local-data/mongodb`; it never uses this fallback in production. The MongoDB binary may download on first run. Stop with Ctrl+C before restarting; do not run two local development instances against that directory. This is a separate local journal, not a copy of your deployed accounts or trades.

```sh
npm ci
# Optional: copy .env.example to .env and configure your own MongoDB.
# Without MONGODB_URI, development starts its persistent local database.
npm run dev
```

Open http://localhost:3000. Passwords require at least six characters with no mandatory character classes. Authentication now uses server-verified cookies; existing users must log in again. Existing bcrypt passwords and records remain supported.

Optional Cloudinary keys enable screenshots. New images use authenticated storage and an owner-checked delivery proxy. Existing public image URLs remain unchanged. AI development is paused by request. Keep `AI_ENABLED=false`; the active workspace has no AI controls. Existing stored insights are retained.

## Verification

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium firefox webkit
npm run test:e2e
npm audit
```

`lint` is the repository's TypeScript check, not a separate ESLint ruleset. Vitest and browser tests create disposable MongoDB servers and use synthetic users/trades. They do not use your production database. MongoDB and Playwright binaries may download on first run. Browser tests use HTTPS on port 3100 with a temporary self-signed certificate generated by OpenSSL, and test the built app; build before running them. Certificate validation is bypassed only by the test runner. Chromium desktop/tablet/mobile, Firefox desktop, and WebKit mobile are configured.

## Staging and deployment checklist (not executed)

1. Back up MongoDB. Inspect duplicate normalized emails, checklist dates and any existing submission IDs. Test new indexes on a disposable copy; see docs/SECURITY_AUDIT.md.
2. Set MONGODB_URI, MONGODB_DB, APP_ORIGIN to the exact HTTPS deployment origin, and optional Cloudinary credentials. Leave AI_ENABLED false until authorized. Never use VITE_ prefixes for secrets.
3. For Express, build then run `NODE_ENV=production npm start` behind a trusted HTTPS reverse proxy. Server binds loopback; configure PORT as needed. Confirm proxy IP handling before changing trust settings.
4. For Vercel, use the existing Vite build and single `api/index.ts` function with the configured API rewrite. Keep server helpers outside `api/` to stay within function limits. Verify Node runtime, sharp packaging, route paths, request limits, MongoDB reachability and headers in staging. Vercel deployment itself has not been tested.
5. Test two-account isolation, cookie Secure/HttpOnly flags, signup/login/logout/password change, trade CRUD, settings/habits, real image upload/delivery and failure states. Inspect existing public media exposure separately.
6. Obtain owner approval before pushing or deploying. No destructive migration or automatic recalculation of historical P&L is included.
